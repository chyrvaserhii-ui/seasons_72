# 72 сезонів природи — брейншторм мобільного застосунку

## Концепція

Японський традиційний календар **七十二候 (Shichijūni-kō)** ділить рік на 72 мікро-сезони, кожен триває ~5 днів. Вони згруповані в 24 більші сезони **二十四節気 (Nijūshi-sekki)**, які, в свою чергу, утворюють 4 сезони **四季 (Shiki)**. Кожен мікро-сезон має поетичну назву — опис конкретного явища природи (наприклад, «Східний вітер топить лід», «Солов'ї починають співати»).

---

## Основні можливі features (від мінімальних до амбіційних)

### 🟢 MVP (must-have)

1. **Екран «Зараз»** — поточний мікро-сезон з поетичною назвою (JP + укр/англ), датами, коротким описом, ілюстрацією/фото.
2. **Тижневий/місячний контекст** — який був попередній мікро-сезон, який буде наступний, і коли він почнеться.
3. **Повний календар 72 сезонів** — скроллабельний список з групуванням по 4 великих сезонах.
4. **Push-сповіщення про зміну мікро-сезону** — коротке поетичне повідомлення на початку кожного нового kō (раз на ~5 днів).

### 🟡 Should-have (на другій хвилі)

5. **Home Screen віджет** (iOS WidgetKit + Android Glance/AppWidget) з:
   - поточним kō,
   - ілюстрацією сезону,
   - прогресом в межах поточного 5-денного циклу (через скільки днів наступний).
6. **Lock Screen віджет** (iOS 16+) — компактний віджет з назвою kō.
7. **Фонове зображення (wallpaper)** — можливість зберегти поточне зображення сезону як шпалери через системний share-sheet.
   - ⚠️ Автоматична зміна wallpaper технічно неможлива на iOS без user interaction. На Android частково можлива через `WallpaperManager` API.
8. **Щоденна нотатка природи (journal)** — користувач може додати свою замітку/фото до кожного сезону, створюючи особистий «альманах року».

### 🔵 Nice-to-have

9. **Sound of season** — короткий ембіент (спів птахів, дощ, вітер) для поточного сезону.
10. **Геолокаційна адаптація** — порівняння японських kō з локальною погодою («У Японії зараз "Сакура вперше розквітає", а у Києві ще сніжить»).
11. **Haiku generator** — випадкове хайку, пов'язане з поточним сезоном.
12. **Поділитись сезоном** — красива share-картка з назвою kō та датою для соцмереж.
13. **Apple Watch / Wear OS complication** — назва kō прямо на циферблаті.
14. **Темна/світла тема + сезонні колірні палітри** (4 основні палітри, що плавно перетікають).
15. **Lunar mode** — додатково показувати місячні фази, бо вони теж важливі для японської традиції.

## Технічні рішення та архітектура

### Stack

- **Flutter 3.x** (Dart) — спільна кодова база iOS + Android.
- **State management**: Riverpod (простіший і сучасніший за Provider, краще тестується за BLoC для такого простого кейсу).
- **Локальна БД даних сезонів**: JSON-файл в assets (72 записи — це зовсім небагато). Не потрібен SQLite/Hive.
- **Сховище для користувацьких нотаток** (якщо реалізуємо журнал): `drift` або `isar` або простий `shared_preferences` для MVP.
- **Локалізація**: `flutter_localizations` + `intl`. Підтримка: JP, EN, UK (мінімум), пізніше RU.
- **Нотифікації**: `flutter_local_notifications` — для всіх 72 сезонів планується по одному локальному сповіщенню на рік наперед (iOS ліміт — 64 pending notifications, тому треба ротація, про це нижче).
- **Віджети**:
  - iOS: `home_widget` + нативний Swift код з WidgetKit.
  - Android: `home_widget` + AppWidgetProvider (Kotlin) або Jetpack Glance.
- **CI**: GitHub Actions — build iOS/Android, dart analyze, тести.

### Розрахунок дат мікро-сезонів

Дати kō **не фіксовані** — вони залежать від сонячних довгот і змінюються на ±1 день щороку. Два варіанти:

- **Варіант A (простий, для MVP):** зашити усереднені дати (наприклад, «Risshun = 4–8 лютого щороку»). Точність ±1 день, для користувача майже не помітно.
- **Варіант B (точний):** рахувати через астрономічні формули (сонячні еклиптичні довготи в кроки по 5°) — є готові JS/Python алгоритми, можна портувати на Dart. Бібліотеки: рахувати самому, бо готових Flutter-бібліотек для sekki немає.

Рекомендую **A для MVP, B потім**.

### Нотифікації: ключовий технічний момент

- **iOS**: ліміт 64 pending local notifications. Рішення: при старті застосунку планувати лише наступні ~60 сповіщень; при відкритті застосунку (будь-якому) доплановувати нові.
- **Android**: ліміт вищий (500+), але все одно варто використовувати WorkManager/AlarmManager через `flutter_local_notifications` для перепланування.
- **Background refresh**: iOS `BGAppRefreshTask` — обмежений, але достатньо, щоб раз на тиждень оновити розклад.
- **Тримати фактичну дату переходу у конфігурації**, яка підтягується з bundled JSON.

### Віджети (home screen)

- `home_widget` 0.6+ передає дані з Flutter у нативний widget extension через UserDefaults (iOS) / SharedPreferences (Android).
- Окремий таргет у Xcode project для WidgetKit extension.
- Оновлення віджета — раз на годину (timeline provider), плюс після відкриття app.

### Wallpaper

- **iOS**: не можна програмно змінити wallpaper. Можна тільки:
  - Зберегти в Photos (`image_gallery_saver`) + показати user → далі він сам ставить.
  - Можна зробити Shortcuts Automation — складніше для юзера.
- **Android**: `WallpaperManager.setBitmap()` — працює, потрібен permission `SET_WALLPAPER`.
- Висновок: **автоматична зміна — тільки Android**, на iOS — півкроку (share у Photos).

## Контент (що реально потрібно буде створити)

- 72 текстові описи сезонів (JP romaji + JP kanji + EN + UK переклад).
- 72 ілюстрації / фото. Варіанти джерел:
  1. **Public domain японські гравюри ukiyo-e** (наприклад, Hokusai, Hiroshige) — безкоштовно, стилістично ідеально. Через Wikimedia Commons / The Met Open Access.
  2. **Власні AI-генеровані ілюстрації** в єдиному стилі (наприклад, sumi-e).
  3. **Ліцензовані фото** — дорого.
- Рекомендую **старт з ukiyo-e**, плюс згодом свій AI-сет.
- Опціонально: 72 короткі ембіент-семпли (10-20 сек each) — з Freesound (CC0).

3. **Ілюстрації**: ukiyo-e (класика, безкоштовно) чи щось сучасніше/мінімалістичне?
4. **Масштаб MVP**: швидкий прототип (1-2 екрани, працююча концепція) чи повноцінна заготівля під App Store?
5. **Власні дати чи «як у Японії»?** — японський календар має ~4-годинну різницю з Україною, але для мікро-сезонів це практично не має значення.

## Що пропоную зробити зараз у цій сесії

**Крок 1** (зараз): Створити scaffold Flutter-проекту з усім каркасом:
- Структура тек (`lib/features/season/`, `lib/core/`, `assets/seasons.json`).
- Повний JSON з усіма 72 сезонами (JP + EN; UK додамо потім).
- Головний екран «Зараз» з логікою визначення поточного kō.
- Екран повного списку.
- Базова тема.
- README з інструкцією запуску (`flutter run`).

**Крок 2** (пізніше): Нотифікації + віджет — коли проект уже має каркас і можна тестувати локально.

Ця стратегія дозволяє перевірити концепцію максимально швидко, а потім нарощувати функціонал по пріоритету.
